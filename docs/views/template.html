What each embedding choice buys on a real retrieval task

NFCorpus: 3,633 medical abstracts and 323 test questions with graded relevance labels. Each card changes one choice in the retrieval pipeline and measures it. Every number comes from the command under its chart.

how retrieval works

Text becomes a vector, the closest vectors win

chunkingCut the textLong documents are split into passages; what you embed is not always what you return.
modelEncode tokensA transformer turns each token into a vector that depends on its neighbours.
poolingOne vector per textAverage the token vectors (mean) or keep the first one (CLS).
dimensionsNormalize, maybe shrinkUnit length makes dot product equal cosine; PCA or cutting saves memory.
indexFind the nearestExact search compares with every vector; HNSW walks a graph and skips most.
metricScore the rankingNDCG@10 rewards relevant documents near the top, more for highly relevant ones.
pooling and similarity

Use the pooling and similarity the model was trained with

MiniLM was trained with mean pooling and cosine similarity. Taking the CLS vector instead costs 0.025 NDCG@10, and ranking raw vectors by dot product costs 0.031.

approximate search

HNSW gets faster than exact search as the corpus grows, and gives up some recall

Exact search time grows with the corpus. HNSW stays near a millisecond, at the cost of missing some of the true top 10. ef sets how hard each query searches. Beyond 3,633 documents the corpus is padded with random vectors, not real documents, so the overlap there may differ on real data.

domain fine-tuning

Fine-tuning on this domain did not move the scores beyond noise

Two kinds of contrastive training, 3 seeds each, scored on test questions whose texts no run saw. Every interval includes zero. Title-to-abstract pairs teach MiniLM nothing new; its training data already holds such pairs. The train-question runs lowered NDCG@10 and raised Recall@100 in every seed, but by less than the noise. A one-seed run had shown a "significant" drop that more seeds erased.

vector size

Projecting onto the corpus's main directions keeps almost all quality at a third of the size

Fewer dimensions mean less memory and faster search. Cutting keeps a vector's first coordinates. SVD projects onto the directions that carry most of the corpus's vectors. PCA does the same after subtracting the corpus mean, and that shift alone costs quality: with all 384 dimensions kept, PCA scores 0.2916 against 0.3186.

uv run el dims
chunking

Small chunks find more, and auto-merging does it with the least text

Each long document hides one gold abstract among nine unrelated ones. Each strategy is compared with fixed 8-sentence chunks on the same 100 questions. Big 32-sentence chunks blur the match. Auto-merging finds more while returning fewer sentences.

uv run el chunks
